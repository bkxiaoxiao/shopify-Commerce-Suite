# 实现范围和验收边界

本清单区分可执行代码、配置前提和仍待开发的方案项。开发方案中的 16–24 周完整对齐范围不会因生成部署文件而被标记为全部完成。

## 可以运行的核心链路

1. 允许的员工从 Shopify App Bridge 打开应用，或公司管理员用独立密码登录。OAuth 在准确的店铺 allowlist 内完成；离线访问令牌和续期令牌用 AES-256-GCM 加密保存。API/Secret 不返回前端。
2. 商品同步任务读取真实变体、价格、重量、库存及地点状态。前台推荐还通过当前国家的 Storefront 可售和价格校验；组合只将实际商品加入购物车。原生 BXGY 和 Plus Functions 均由 Shopify 执行结账优惠，不接受浏览器传来的优惠金额。
3. 运费规则经验证后存入 PostgreSQL。CarrierService 注册后，Shopify 使用随机回调凭据请求报价；币种不符、重量缺失、超出区间、禁运地区不会返回免费费率。没有完整购物车上下文时不拼凑局部商品组报价。
4. 已验证的 `orders/paid` 事件进入数据库 outbox；按开关使用原订单价格、折扣分摊、税和运费生成发票。金额或数量对不上时失败等待核查，不自行猜税额。`refunds/create` 必须匹配原票和成功退款交易，生成实际部分退款的负额贷项。
5. 报价只用显式输入的币种、整数金额和税率。所有单据使用原子编号和不可变快照；重试同一来源不会重复开票。下载需要当前店铺权限。PDF 为真实文件并嵌入 Noto Sans SC 字体，字体 OFL 许可随源代码提供。
6. 订阅绑定 email、variant 和国家；补货通知与营销同意分开。记录已知线上库存从 0 到正数的变化；邮件队列处理前再次读取真实库存、地点状态和当前市场可售状态。退订后不再发送。提供方请求带稳定幂等键；任务最多 5 次自动尝试，失败保留供管理员核查。
7. 卸载事件立即撤销本地安装状态、清空凭据、停止待发任务。客户隐私删除处理非财务缓存和订阅；财务原票按不可变原则进入法定留存人工复核，不声称自动满足所有国家的法律要求。

邮件重试同时保存固定内容和首次请求时间。超过 23 小时后禁止再次向提供方重试，以避免超过其幂等保留窗口而重复发送；管理员需先核对提供方记录，再决定是否创建新的发送任务。暂停自动补货会延后待发任务并保留次数，不会假报已经发送。

## 部署后需要完成的配置

| 项目 | 必要条件 |
| --- | --- |
| 多店授权 | 非 Plus 多店通常分别创建 App 身份，共用后端时按域名配置 `SHOPIFY_SHOP_CREDENTIALS`；组织与分发能力以实际 Shopify 资格为准 |
| 管理员 | 明确授权员工 ID；未配置员工列表时，不把任意有效 Shopify JWT 当作公司管理员。密码登录可选 |
| 运费 | Shopify CCS 资格，`write_shipping` 授权，承运服务注册及实际配送区域验证 |
| 原生优惠 | 实际变体及 `write_discounts`；原生 BXGY 无法表达任意完整 SKU 组合的所有条件 |
| 精确优惠 | 自用 App 的 Shopify Plus 资格；Function 扩展编译并部署；后端发布后才有真实折扣节点 |
| 前台 | `write_app_proxy`、签名 App Proxy 和主题扩展；不要继续保留旧 App 的重复组件 |
| 补货 | 已同步库存基线、Storefront 私有 token（按店铺配置）、线上地点与市场发布状态、自动提醒开关 |
| 单据 | 真实开票主体、地址、VAT、语言；财务审核样例，自动发票/贷项开关 |
| 邮件 | Resend API key、验证过的 MAIL_FROM、真实测试收件人；发件主体邮箱字段本身不会替代域名验证 |
| 调度 | Cloud Scheduler 每分钟向 `/internal/jobs/run` 发 POST，并带独立任务 secret；无调度时，记录只会可靠排队，不会假报完成 |

## 方案中仍待开发的高级范围

| 范围 | 当前边界与待办 |
| --- | --- |
| 复杂运费 | 多 shipping profiles/多仓合并、承运商实时报价、按客户/B2B 身份规则、独立低延迟缓存与报价日志/监控面板；目前不能证明载荷中未提供的身份或整车条件 |
| 推荐与转化 | 真实共购训练、随机策略、评价组件、购物车/结账位置扩展、完整成交归因、自动实验；生产分析页缺数据时显示待接入 |
| 商品规模 | 管理台每类列表目前最多 1000 行；商品分页同步每次 1 个商品、前 10 变体及每变体前 20 地点，以控制 Shopify 查询成本。截断有标记，补货决策拒绝不完整库存；更多变体/地点的完整分页和批量同步仍需扩充 |
| 全部单据类型 | 收据、装箱单、退货表、草稿订单等全部格式、可视化模板编辑器、批量打印、历史回填和人工金额调整流程 |
| 报价收款 | 报价转 Shopify 草稿订单/付款链接、部分支付、余额及催款；Stripe/PayPal/线下付款对账没有实现，不提供虚假的付款按钮 |
| 文档归档 | PostgreSQL 已保存不可变快照；私有对象存储 PDF 存档、Drive/Dropbox/FTP、断点补传、目录规则仍待实现。GCS_BUCKET 当前仅保留参数，没有启用归档 |
| 账户及 POS | 客户账户/订单状态页下载扩展、POS 预览与打印均待开发；当前只有管理员鉴权下载 |
| 补货扩展 | Mailchimp 连接器、发送批次/频控、邮件送达/退信回调、SMS/WhatsApp、触达归因和完整多语言模板编辑器 |
| 合规运维 | GDPR 安全数据导出界面、国家级结构化电子发票、法定留存规则自动化、数据库恢复演练、全量迁移、告警、真实多实例和性能验收 |

## 验收记录方式

分别记录：本地检查、Docker 镜像构建、Cloud Run 部署、真实店铺验收。不能把某一项通过推断为其余项通过。邮件任务完成表示提供方接受发送请求；最终送达需要后续邮件事件支持。压力、税务、迁移及平台资格没有测试证据时保留待验收。
